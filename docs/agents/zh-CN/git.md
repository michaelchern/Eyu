# Eyu Git Workflow Context

只在 `=br`、`=gc`、`=cm`、`=gh`、分支、提交、推送、PR 或发布检查任务中加载本文件。

## 分支命名

分支使用 `<type>/<english-kebab-description>`，不添加工具名、用户名或日期前缀。允许的 `type`：

- `feat`：新增语言或工具行为。
- `fix`：修复错误行为。
- `docs`：只修改文档、Agent 资料或学习记录。
- `refactor`：不改变外部行为的结构调整。
- `perf`：性能或资源优化。
- `test`：测试和测试数据。
- `build`：CMake、依赖、preset 或工具链。
- `style`：只做格式、注释或文本风格调整。
- `chore`：其他仓库维护。
- `spike`：临时语言实验或技术验证。

描述只使用小写字母、数字和单连字符，完整名称不超过 63 个字符，并通过 `git check-ref-format --branch`。

## `=br <用途>`

1. 查看当前分支、`HEAD` 和工作区状态。
2. 检查已知本地与远程引用，不为命名自动 fetch。
3. 推导并校验分支名。
4. 同名引用存在时停止询问，不自动追加后缀或切换已有分支。
5. 默认从当前 `HEAD` 使用 `git switch -c` 创建；保留未提交改动，不 stash、reset、clean 或回滚。
6. 只创建并切换分支，不提交、推送或创建 PR。

## `=gc`

- 不修改文件。
- 检查 `git status --short --branch`、相关 diff 和未跟踪文件。
- Agent 文件运行同步检查；源码、CMake 或测试运行最小相关验证。
- 汇报准备纳入的文件、风险和验证结果。

## `=cm`

- 检查状态、diff 和验证结果。
- 只暂存当前任务文件，不默认 `git add .`。
- 暂存后运行 `git diff --cached --check` 和相关验证。
- 使用简洁标题和中文正文，说明改了什么、为什么以及验证了什么。
- 创建本地提交后停止，不推送或创建 PR。

## `=gh`

- 执行 `=gc` 范围检查并完成相关验证。
- 如有未提交改动，按 `=cm` 规则提交。
- 推送当前分支到 `origin`，创建 draft PR。
- 汇报分支、commit、PR URL 和验证结果。

## 安全规则

- 不覆盖无关工作区改动，不暂存无关文件。
- 验证失败时默认不推送，除非用户明确要求继续。
- `=cm` 绝不推送或创建 PR；`=gh` 默认创建 draft PR。
